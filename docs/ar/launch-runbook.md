# دليل الإطلاق

دليل عملي مختصر لنقل المنتج من "مبني ومختبر محليًا" إلى "حضانة حقيقية
تستخدمه". للتفاصيل الكاملة لكل خطوة راجع النسخة الإنجليزية
`docs/en/launch-runbook.md` — هذا ملخص للنقاط الأساسية.

## قبل البدء

راجع كل بند في `docs/NEEDS_FROM_ME.md` وتأكد من إنجازه أو تأجيله بوعي:
مشروع Supabase، مراجعة العلامة التجارية، النطاق الإلكتروني، المراجعة
القانونية (لا تتخطَّها عند التعامل مع بيانات أطفال حقيقيين)، ومراجعة
النصوص العربية إن كنت ستستخدمها مع عائلات حقيقية.

## الخطوات الرئيسية

1. **تطبيق مخطط قاعدة البيانات**: شغّل كل ملفات `supabase/migrations/`
   بالترتيب، ثم `npm run db:seed` لزرع الموضوعات والباقات. لا تشغّل
   `npm run db:reset` على مشروع حقيقي — فهو مخصص للعرض التجريبي المحلي
   فقط.
2. **إعداد Supabase Auth**: تفعيل تسجيل الدخول بالبريد، ضبط روابط
   الموقع الحقيقية، تفعيل المصادقة الثنائية (مفعّلة افتراضيًا وتتطلبها
   لوحة تحكم المالك).
3. **متغيرات البيئة**: انسخ جميع المتغيرات من `.env.example` إلى إعدادات
   الاستضافة، مع إبقاء أعلام الميزات الحساسة (`FEATURE_REAL_IMAGE_PROVIDER`،
   `FEATURE_BILLING`) معطّلة حتى تكتمل متطلباتها.
4. **النشر**: تأكد من نجاح `npm run build` محليًا أولًا، ثم انشر عبر
   مزود الاستضافة.
5. **إعداد المُجدوِل (Cron)**: يجب أن يستدعي شيء ما `/api/cron/worker`
   كل دقيقة إلى دقيقتين لمعالجة طابور توليد القصص.
6. **اختبار ما بعد النشر**: نفّذ الفحوصات الثمانية في
   `docs/TEST_CHECKLIST.md` على الرابط الحقيقي المنشور.

## المراقبة والنسخ الاحتياطي

لا توجد أدوات مراقبة مدمجة بعد — فعّل لوحات السجلات المدمجة في مزود
الاستضافة وSupabase على الأقل. تأكد من أن باقة Supabase تتضمن نسخًا
احتياطية تلقائية واختبر عملية استرجاع واحدة قبل الحاجة إليها فعليًا.

## خطة الاستجابة للحوادث

أي احتمال لتسرّب بيانات طفل هو حدث ذو صلة بقانون حماية البيانات
الإماراتي — أشرك المراجع القانوني فورًا. لإيقاف الإنفاق على الذكاء
الاصطناعي فورًا، عدّل `global_spend_cap.kill_switch = true` مباشرة في
قاعدة البيانات. أي بلاغ عن رؤية مؤسسة لبيانات مؤسسة أخرى يُعامل كحادثة
من الدرجة الأولى فورًا.
